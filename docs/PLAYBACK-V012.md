# 0.12.0 动作连播与缓存

壁纸中心顶部的「播放缓存」打开缓存管理。也可在任意壁纸的「画质 / 管理素材」页面找到同一区域。

## 使用方式

- 默认开启，磁盘上限为 2GB，可选择 512MB、1GB、2GB、4GB、8GB，或关闭。
- 播放官方皮肤时，优先处理当前与下一张皮肤。原片和 4K 分开缓存，同一份缓存可在多个队列中复用。
- 缓存就绪后，在下一遍或下次进入该皮肤时生效，不从头打断正在播放的动作。整套动作仍按原编号播放，队列默认两遍和自定义遍数保持。
- 「重建此皮肤缓存」重新检查当前选中皮肤。正在使用的版本保留，替代版本完成后才交接。
- 「清理闲置缓存」只清理播放缓存；正在使用及马上要播放的内容会保留。不会删除原片、4K 素材、队列或组合。
- 容量不足、缺少 FFmpeg、素材参数不兼容时继续使用增强的分段播放。可以从资源页「配置可选视频工具」选择 FFmpeg，再重建缓存。普通播放不强制安装它。

## 资源占用边界

后台壁纸常驻最多两个视频解码槽位；不会把整条队列解码到内存，也不会把整段 4K 文件放进 JavaScript Blob 池。手动预览按需开启，关闭预览或离开页面后释放。

独立保护画布按视口大小分配，最高 1920×1080，RGBA 像素约 7.9MiB；不持续逐帧复制 4K 画面。该数值仅是保护画布像素预算，不是整个客户端的内存或显存上限。浏览器解码器和 GPU 驱动仍有自身开销。

缓存构建一次一个任务，FFmpeg 解码检查使用一个线程、低进程优先级，合并使用 streamcopy 并限制读取节奏。读取源文件哈希时使用 256KiB 分块并让出事件循环。正在下载/处理素材或检测到近期播放卡顿时，暂缓缓存构建。快速切换壁纸会取消不再需要的自动任务。

缓存磁盘预算包含现有完成文件和新任务预留；正在使用的文件不能被淘汰，因此调整到低于当前受保护文件占用的上限时，不会强行删除这些文件，后续有机会再清理。缓存构建还预留 128MB 磁盘余量。

## 接缝处理

已确认的极短、近乎均匀的边界黑帧记录有效播放范围，原视频不改写。正常暗场与渐变不会仅因亮度低就自动裁掉。最初四段本地视频继续沿用安全的片尾避让。

符合参数要求的皮肤合并为一份无重编码视频，动作时间索引保留逻辑顺序。同一皮肤内部不再反复重建解码器。需要内部逐帧修剪、编码参数不同的素材保留分段播放，不自动重新编码或重新超分。

分段和整套循环均要求实际视频帧及后续缓冲就绪。下一段迟到时保留最后有效画面；新表面完成交接后才回收旧槽位。调透明度、缩放或不影响紧接后继的队列编辑不丢弃已预载内容。原片/4K 更换在动作或整套的安全边界生效。

素材之间原本的姿态跳变不会被解释为加载卡顿，也不使用 AI 改动作。低性能机器仍可选择原片或省资源模式。

## 数据与维护

数据位于 `.local/playback-cache-v2/`，源码包和 Windows 包均不包含这些文件。索引按源素材指纹、画质、边界信息和算法版本失效；不会在心跳内重复哈希大视频。失败或中断的临时文件在退出/下次启动时清理，只有当前缓存目录内的已知文件允许删除。

复核脚本：

- `node --test tests/*.test.mjs`：含缓存边界、持久化、保护删除和源文件不变性。没有配置 FFmpeg 时相关集成项明确跳过。
- `scripts/playback-cache-check.mjs`：本机四套真实皮肤原片/4K 的缓存生成及帧数检查，需已有素材和 FFmpeg。
- `scripts/action-seams-check.mjs`：隔离浏览器中超过 100 次自然交接，采样实际合成截图，另测延迟下一段、暂停恢复和构图编辑。
- `scripts/native-seams-soak.mjs 1800`：真实客户端已有队列播放 30 分钟，仅采样壁纸图层；结束恢复原播放选择。如果用户改变播放状态则结束验收并保留用户选择。

验收结果详见 `docs/PLAYBACK-V012-VERIFICATION.md`。截图/像素采样和帧回调诊断不能替代所有硬件、驱动与客户端版本的实机验收。
