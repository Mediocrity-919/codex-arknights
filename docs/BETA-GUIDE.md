# Windows 测试版使用说明

## 运行、安装和恢复

解压 Windows ZIP 到独立、可写的文件夹。双击 `ARK启动Codex.cmd` 可直接运行；无需安装 Node。系统需已有 Codex / ChatGPT Windows 客户端。默认壁纸是包内原创背景；素材目录只含元数据，不包含整套视频和立绘。

双击 `安装.cmd` 默认安装到 `%LOCALAPPDATA%\ArkWorkspace`，创建单独的桌面入口并登记到当前用户的 Windows 应用卸载列表。安装不需要管理员权限。高级用法：`scripts/Install-Theme.ps1 -Destination <独立目录> -BindExistingShortcuts` 会备份并绑定扫描到的现有入口。`恢复原启动入口.cmd` 依据备份恢复；外部已修改的快捷方式不会覆盖。

双击安装目录里的 `卸载.cmd`，会先停止主题助手、恢复本安装绑定的入口，再按安装清单删除未被修改的程序文件。默认保留素材和个人设置。确需清理时显式使用 `scripts/Uninstall-Theme.ps1 -RemoveUserData`；它只清理已知数据位置和目录列出的素材文件，不删除整个任意安装父目录。

用户数据放在该安装目录的 `.local`，因此可移植目录需要写入权限；不要放进只读的 Program Files。移动已安装目录前应先恢复快捷方式，再在新位置重新安装。更新前备份 `.local`；测试版暂不提供联网自动更新。

卸载保留数据后可以重新安装到同一目录。重装时会保留个人数据，把将被替换的已修改程序文件备份到 `.local/program-backups/`。

## 已存组合怎样用

1. 在壁纸页面选择背景/干员组合或完整壁纸，点击“放大编辑 / 拖动构图”。
2. 调整背景和人物各自的缩放、位置，给构图命名，点击“保存组合”。保存后不会立即更换正在使用的壁纸。
3. 从页面顶部“已存组合”打开，点击“应用壁纸”使用，也可加入指定播放队列。
4. 从组合打开后再保存会更新同一个组合；“另存一份”创建新组合，自动处理重名，不覆盖其他构图。
5. “管理组合与使用说明”中可重命名、打开或删除构图。删除不删素材、不删队列；本次会话可撤销最近一次删除。

组合保存壁纸、背景和图层构图。页面透明度、输入框透明度、明暗遮罩和磨砂仍是全局外观设置。队列中加入组合时复制一份构图快照，后续编辑已存组合不会悄悄改动已有队列项。

## 素材下载、画质和删除

选择一张壁纸，点击“下载 / 管理素材”。静态图按单张下载；动态按所选时装/晋升立绘的一整套动作下载，动作仍按原顺序连播。普通 PNG、MP4 不需要 Python。

- 原片：下载来源图片或完整展示视频，保留原画幅。已下载时该按钮选择原片画质。
- 4K：先取得原片，再在本机通过可选 AI 工具生成；已有本地 4K 时可直接使用。不会把超分标成官方原生 4K。
- 工具：资源中心“配置可选视频工具”可选择本机 FFmpeg，以及可选的 Python、模型目录。配置器验证后自动刷新可用功能。首次配置 AI 环境仍需独立安装依赖，详见 `tools/resource-fetcher/README.md`。
- 任务：显示下载/处理进度，可取消或失败后重试。中断后的部分下载用于续传；AI 当前片段会重做，已完成片段保留。
- 删除：选择仅原片、仅 4K 或全部，先检查文件大小及队列/组合引用，再确认。正在使用的素材不可删除。删除保留构图引用，再次播放前需重新下载。

播放偏好可以跟随各壁纸的选择，或全局优先原片/4K。省资源模式使用原片；自动模式在 4K 播放近期连续出现多次较长帧间隔时，尝试在本次会话回退原片，保留当前画面直到替代素材就绪。后台与系统减少动态效果设置仍可暂停动态。自动回退不能保证所有设备在任意负载下都流畅，应结合实际设备验收。

目录来自 2026-10-24 快照；来源链接可能更新或失效，出现这类错误需更新目录。预览图按选择缓存；无需先下载整个库。公开快照和获取说明不是素材分发授权。

## 验收范围与尚待验证

0.12.0 新增「播放缓存」：在壁纸中心顶部打开，可调整磁盘上限、重建当前皮肤缓存或清理闲置缓存。默认 2GB，只按需无重编码合并；源素材保留，不再执行一轮超分。没有配置 FFmpeg 时仍能分段播放。具体占用边界和使用方式见 [动作连播与缓存](PLAYBACK-V012.md)。

当前已验证启动器 ready/delay/failure/skip/timeout 五个分支、文件资源按需下载与校验、合成 HLS 合并，以及三帧 CUDA 4K 转换。组合和队列的保存恢复、原生输入区恢复、窗口置顶交接有独立验证。

附件弹窗与其他应用遮挡问题已在当前真实客户端取消置顶后由用户确认恢复。结构变化回退、多个独立页面隔离使用模拟宿主检查；没有声称已覆盖未来客户端版本或多台硬件。

真实冷启动需要保存工作并完整退出 Codex 后运行 `冷启动验收.cmd`。它不会强制关闭客户端；通过后在 `.local/cold-start-verification.json` 记录首帧、启动器退出、WebView释放和窗口层级。当前开发聊天中的真实冷启动尚未执行。

当前仅向一个已验证主窗口接入主题；有多个候选时优先当前聚焦的窗口，也可在本地实验室手动选目标。其他窗口保持原功能。发布前还需在干净 Windows 机器和不同 DPI/多屏环境做实机试用。
